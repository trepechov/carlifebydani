### Featured image (id 4117) — two separate writes, not one
| Field | Before | After |
|---|---|---|
| Media library `alt_text` | *(empty)* | `Китайски електромобили превземат европейския пазар` |
| Media library `title` | *(empty)* | `Китайски електромобили в Европа` |
| **`post_content`'s own `wp:image` block `alt` attribute** | `alt=""` (baked into the block at insert time) | `alt="Китайски електромобили превземат европейския пазар"` |

**New finding, not previously documented in this skill's traps:** this
image is embedded via a standalone `wp:gallery`/`wp:image` block directly in
`post_content` (not as the post's `featured_media` reference rendering
dynamically) — its `<img alt="">` is a **static snapshot** written into the
block at insert time, not a live pointer to the media library's `alt_text`.
Writing `POST /wp/v2/media/<id>` alone (the skill's documented mechanic)
updates the media library record but **does not** change what's actually
rendered on this specific page — confirmed by re-fetching the rendered page
after the media-only write and finding `alt=""` still live. Required a
second, separate edit directly inside `post_content`'s block markup (same
mechanics as an inbound-link edit — locate the block, change only its
attribute, resend the full content). **Worth adding to
`seo-article-apply`'s Known Traps** for any future post whose featured/hero
image is embedded via its own `wp:image` block rather than purely as
`featured_media` — check both before calling an alt-text fix complete.
